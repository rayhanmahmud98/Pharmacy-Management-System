# Phase 0 — Architecture & Master Specification Blueprint
**Product:** MediNest — Offline-First Pharmacy Management Software

## 1. Environment & Stack Adaptation Note
- **Runtime Host:** This workspace executes as a full-stack Node.js v22 + Express (`server.ts`) + React + Tailwind CSS application on `0.0.0.0:3000` (configurable via `BIND_HOST` and `PORT`) with `node:sqlite` (SQLite 3 in WAL mode + native SQLite Online Backup API).
- **Zero-Compromise Business Invariants:** Every financial, inventory, FEFO, manual unit conversion, RBAC, hash-chained audit, backup SHA-256 verification, atomic HTTP idempotency, and offline Ed25519 licensing invariant is enforced in the backend service layer inside atomic SQLite transactions (`BEGIN IMMEDIATE ... COMMIT / ROLLBACK`, with SQLite `SAVEPOINT` support for nested transaction boundaries).

## 2. Database Schema & Entity Model (UUID PKs + Human-Readable Numbers)
- **Core & Settings:** `pharmacy_settings` (pharmacy name, drug license no, address, phone, email, website, currency, timezone, default low-stock threshold, session timeout, logo, expiry warning days, backup retention, printer type, setup_completed).
- **Accounts & RBAC:** `roles`, `permissions`, `role_permissions`, `users` (with `role_id`, `is_active`, `is_super_admin`, `must_change_password`), `user_permission_overrides` (explicit `ALLOW` / `DENY` per user + permission), `sessions`. Seeded accounts require mandatory password update before accessing operational endpoints.
- **Medicine Master & Manual Units:** `categories`, `manufacturers`, `medicines` (medicine_code, barcode, brand, generic, strength, dosage_form, storage_info, base_unit_name, min_stock_level, rx_required, is_active), `medicine_units` (manual per-medicine `unit_name`, `conversion_to_base` Decimal > 0, `allow_purchase`, `allow_sale`, `is_base`, `is_active`). Never hardcoded.
- **Inventory & Ledger:** `batches` (`medicine_id`, `batch_number`, `expiry_date`, `supplier_id`, `purchase_id`, `purchase_cost_per_base`, `selling_price_per_base`, `initial_qty_base`, `current_qty_base`, status: `ACTIVE | QUARANTINED | EXPIRED | WRITTEN_OFF | INACTIVE | DEPLETED | DAMAGED`), `stock_movements` (immutable ledger: `OPENING_STOCK | PURCHASE_RECEIVED | SALE | SALE_RETURN | PURCHASE_RETURN | ADJUSTMENT_IN | ADJUSTMENT_OUT | DAMAGE_WRITEOFF | EXPIRY_WRITEOFF | SALE_REVERSAL | PURCHASE_REVERSAL`). Receiving additional stock into an existing active/depleted `(medicine_id, batch_number, expiry_date)` batch recalculates `purchase_cost_per_base` using 6-decimal Weighted Average Cost (`computeWeightedAverageCost`).
- **Purchasing:** `suppliers` (including `current_balance` and `advance_balance`), `purchases` (`PUR-YYYYMMDD-XXXX`, status `DRAFT | RECEIVED | CANCELLED | REVERSED`, `advance_applied`), `purchase_lines` (`conversion_ratio_snapshot`, `qty_input`, `qty_base`, `unit_cost`, `line_discount`, `line_total`), `purchase_returns` (`PRN-...`, `due_settled`, `advance_created`), `purchase_return_lines`.
- **Sales & POS:** `customers` (including `current_balance`, `advance_balance`, `credit_limit`), `sales` (`INV-YYYYMMDD-XXXX`, status `DRAFT | COMPLETED | CANCELLED | REVERSED`, `gross_subtotal`, `line_discount_total`, `invoice_discount`, `net_total`, `paid_amount`, `due_amount`, `advance_applied`, `total_cogs`), `sale_lines` (`unit_name_snapshot`, `conversion_ratio_snapshot`, `qty_input`, `qty_base`, `unit_price`, `line_discount`, `line_total`, `effective_line_total`, `cogs_total`), `sale_batch_allocations` (`batch_id`, `qty_base`, `cost_per_base_snapshot`, `cogs_total`, `is_manual_override`, `override_reason`).
- **Sales Returns:** `sales_returns` (`SRN-YYYYMMDD-XXXX`, linked to `sale_id`, `refund_amount`, `credit_amount`, `due_settled`, `advance_created`, `reason`), `sales_return_lines` (`sale_line_id`, `batch_id`, `qty_base`, `disposition`: `RESTOCK_SELLABLE | QUARANTINE | DAMAGED | WRITE_OFF | NOT_RESTOCKABLE`, `cost_per_base_snapshot`, `cogs_reversed`, `refund_line_total`).
- **Finance, Payments & Cash Sessions:** `cash_sessions` (`CSH-YYYYMMDD-XXXX`, `OPEN | CLOSED | FORCE_CLOSED`, `opening_cash`, `expected_cash`, `actual_cash`, `variance`, `variance_reason`), `cash_movements` (immutable physical drawer ledger; ONLY `CASH` payment method affects drawer), `payments` (`PAY-...`, `method`: `CASH | BKASH | NAGAD | ROCKET | BANK | CARD | OTHER`), `payment_allocations`, `party_advance_ledger`, `expenses` (`EXP-...`, `status`: `POSTED | REVERSED`), `idempotency_keys` (written atomically inside the business transaction).
- **Audit, Backups & Licensing:** `audit_logs` (append-only with SHA-256 hash chain `prev_hash -> entry_hash`), `backup_records` (path, size, `sha256`, `integrity_check_result`, status), `license_state` (signed JSON payload verified exclusively against the embedded Ed25519 public key; private key strictly in developer CLI `tools/generate_license.ts`).

## 3. Non-Negotiable Invariants
1. **Manual Units Only:** Every medicine defines its own `medicine_units`. Sales/Purchases store `conversion_ratio_snapshot` at transaction time so future unit edits never alter historical stock, COGS, or invoices.
2. **Decimal Precision:** All calculations use `decimal.js` (`ROUND_HALF_UP`). Quantities, unit conversions, and per-base cost snapshots support up to **18 integer digits and 6 decimal places**; monetary amounts use up to **18 integer digits and 2 decimal places**. Inputs exceeding allowed precision are rejected strictly without silent rounding.
3. **FEFO Allocation:** Auto-selects `ACTIVE` batches with `current_qty_base > 0` and `expiry_date > today`, ordered by earliest `expiry_date ASC, received_date ASC`. Manual override requires permission + non-empty `override_reason` + AuditLog.
4. **No Silent Deletion / Modification:** Completed sales, purchases, payments, and expenses cannot be deleted or edited; corrections execute compensating reversal/return transactions.
5. **Cash Drawer Isolation:** MFS (`bKash`, `Nagad`, `Rocket`), `Bank`, and `Card` payments update invoice/due balances but NEVER mutate physical `cash_movements`.
6. **Inspection-First & Proportional Returns:** Customer returns never auto-restock without explicit `disposition`. Return valuation honors proportional invoice-level discounts (`effective_line_total`), rejects cumulative duplicate return lines exceeding sold/purchased quantities, caps cash/MFS/bank refunds to remaining invoice `paid_amount`, and settles unpaid invoice dues before creating party advance credit.
7. **Permission Precedence:** `1. Inactive user -> DENY` -> `2. is_super_admin -> ALLOW` -> `3. User Override (ALLOW/DENY)` -> `4. Role Permission -> ALLOW/DENY`.
8. **Backup Integrity & License Read-Only Protection:** Restoring a backup verifies its stored SHA-256 checksum, validates SQLite `PRAGMA integrity_check`, captures a `PRE_RESTORE` backup, and rolls back automatically if post-restore verification fails. Missing, invalid, or expired licenses transition writes to `READ_ONLY` mode while preserving full read access, historical reports, Excel/data export, and invoice reprinting.
