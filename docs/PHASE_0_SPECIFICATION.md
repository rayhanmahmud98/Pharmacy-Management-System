# Phase 0 — Architecture & Master Specification Blueprint
**Product:** ShifaRx — Offline-First Pharmacy Management Software (Bangladesh)

## 1. Environment & Stack Adaptation Note
- **Runtime Host:** This workspace executes as a full-stack Node.js v22 + Express (`server.ts`) + React + Tailwind CSS application on `127.0.0.1:3000` with `node:sqlite` (SQLite 3 in WAL mode + native SQLite Online Backup API).
- **Zero-Compromise Business Invariants:** Every financial, inventory, FEFO, manual unit conversion, RBAC, hash-chained audit, backup verification, and offline Ed25519 licensing invariant from the Master Project Specification is enforced in the backend service layer inside atomic SQLite transactions (`BEGIN IMMEDIATE ... COMMIT / ROLLBACK`).

## 2. Database Schema & Entity Model (UUID PKs + Human-Readable Numbers)
- **Core & Settings:** `pharmacy_settings` (name, Bangla name, license no, address, phone, logo, expiry warning days, backup retention, setup_completed).
- **Accounts & RBAC:** `roles`, `permissions`, `role_permissions`, `users` (with `role_id`, `is_active`, `is_super_admin`), `user_permission_overrides` (explicit `allow` / `deny` per user + permission), `sessions`.
- **Medicine Master & Manual Units:** `categories`, `manufacturers`, `medicines` (brand, generic, bangla_name, strength, dosage_form, base_unit_name, min_stock_level, rx_required, is_active), `medicine_units` (manual per-medicine `unit_name`, `conversion_to_base` Decimal > 0, `allow_purchase`, `allow_sale`, `is_base`, `is_active`). Never hardcoded!
- **Inventory & Ledger:** `batches` (medicine_id, batch_number, expiry_date, supplier_id, purchase_id, purchase_cost_per_base, selling_price_per_base, initial_qty_base, current_qty_base, status: `ACTIVE | QUARANTINED | EXPIRED | WRITTEN_OFF | INACTIVE`), `stock_movements` (immutable ledger: `OPENING_STOCK | PURCHASE_RECEIVED | SALE | SALE_RETURN | PURCHASE_RETURN | ADJUSTMENT_IN | ADJUSTMENT_OUT | DAMAGE_WRITEOFF | EXPIRY_WRITEOFF | SALE_REVERSAL | PURCHASE_REVERSAL`).
- **Purchasing:** `suppliers`, `purchases` (`PUR-YYYYMMDD-XXXX`, status `DRAFT | RECEIVED | CANCELLED | REVERSED`), `purchase_lines` (stores `conversion_ratio_snapshot`, `qty_input`, `qty_base`, `unit_cost`, `discount`, `line_total`), `purchase_returns` (`PRN-...`), `purchase_return_lines`.
- **Sales & POS:** `customers`, `sales` (`INV-YYYYMMDD-XXXX`, status `DRAFT | COMPLETED | CANCELLED | REVERSED`, `gross_subtotal`, `line_discount_total`, `invoice_discount`, `net_total`, `paid_amount`, `due_amount`, `total_cogs`), `sale_lines` (`unit_name_snapshot`, `conversion_ratio_snapshot`, `qty_input`, `qty_base`, `unit_price`, `line_discount`, `line_total`, `cogs_total`), `sale_batch_allocations` (`batch_id`, `qty_base`, `cost_per_base_snapshot`, `cogs_total`, `is_manual_override`, `override_reason`).
- **Sales Returns:** `sales_returns` (`SRN-YYYYMMDD-XXXX`, linked to `sale_id`, `refund_amount`, `credit_amount`, `reason`), `sales_return_lines` (`sale_line_id`, `batch_id`, `qty_base`, `disposition`: `RESTOCK_SELLABLE | QUARANTINE | DAMAGED | WRITE_OFF | NOT_RESTOCKABLE`, `cost_per_base_snapshot`, `cogs_reversed`, `refund_line_total`).
- **Finance, Payments & Cash Sessions:** `cash_sessions` (`CSH-YYYYMMDD-XXXX`, `OPEN | CLOSED | FORCE_CLOSED`, `opening_cash`, `expected_cash`, `actual_cash`, `variance`, `variance_reason`), `cash_movements` (immutable physical drawer ledger; ONLY `CASH` payment method affects drawer), `payments` (`PAY-...`, `CUSTOMER_RECEIPT | SUPPLIER_PAYMENT | SALE_REFUND | PURCHASE_REFUND | REVERSAL`, `method`: `CASH | BKASH | NAGAD | ROCKET | BANK | CARD | OTHER`), `payment_allocations`, `expenses` (`EXP-...`, `status`: `POSTED | REVERSED`).
- **Audit, Backups & Licensing:** `audit_logs` (append-only with SHA-256 hash chain `prev_hash -> entry_hash`), `backup_records` (path, size, sha256, `integrity_ok`, status), `license_state` (signed JSON payload + Ed25519 signature; public key embedded, private key strictly in developer CLI `tools/generate_license.ts`).

## 3. Non-Negotiable Invariants
1. **Manual Units Only:** Every medicine defines its own `medicine_units`. Sales/Purchases store `conversion_ratio_snapshot` at transaction time so future unit edits never alter historical stock, COGS, or invoices.
2. **Decimal Precision:** All calculations use `decimal.js` (`ROUND_HALF_UP`). Quantities/conversions support 4 decimal places; currency uses 2 decimal places.
3. **FEFO Allocation:** Auto-selects `ACTIVE` batches with `current_qty_base > 0` and `expiry_date > today`, ordered by earliest `expiry_date ASC, received_date ASC`. Manual override requires permission + non-empty `override_reason` + AuditLog.
4. **No Silent Deletion / Modification:** Completed sales, purchases, payments, and expenses cannot be deleted or edited; corrections execute compensating reversal/return transactions.
5. **Cash Drawer Isolation:** MFS (`bKash`, `Nagad`, `Rocket`), `Bank`, and `Card` payments update invoice/due balances but NEVER mutate physical `cash_movements`.
6. **Inspection-First Returns:** Customer returns never auto-restock without explicit `disposition`. Only `RESTOCK_SELLABLE` increments sellable batch stock; `QUARANTINE` moves to a quarantined batch; `DAMAGED`/`WRITE_OFF`/`NOT_RESTOCKABLE` record non-sellable write-off without inflating sellable stock.
7. **Permission Precedence:** `1. Inactive user -> DENY` -> `2. is_super_admin -> ALLOW` -> `3. User Override (ALLOW/DENY)` -> `4. Role Permission -> ALLOW/DENY`.
8. **License Expiry Never Locks Customer Data:** Expired or missing licenses transition writes to `READ_ONLY` mode while preserving full read access, historical reports, Excel/data export, and invoice reprinting.
